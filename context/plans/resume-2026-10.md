# Pentaryn Resume — how it was built (2026-10)

**Read this when:** you want to know why `pentaryn-resume` is shaped the way it is. Never load this to operate the module — the use-doc is `context/foundry/resume.md`.

## Goal

Joe (2026-10-16): after the 03:00 nightly restart, a player exploring on their own should log back
in on the screen they had open. The nightly already restores the world and the active scene. What
was missing is per-client: Foundry keeps `viewedScene` only in server memory (`game.activity`),
and `Game#initializeCanvas` always draws `game.scenes.active`.

## Decisions and rejected alternatives

| Decision | Alternatives rejected | Why |
|---|---|---|
| Store the view on the User (a flag) | client setting / localStorage | follows the player across browsers and devices; players may update their own User flags (`BaseUser.#canUpdate`) |
| Resume only while the active scene matches the one saved | always resume; never resume off the active scene | a restart must not move anyone, but a GM who activates a new map at session start expects everyone on it |
| Hold saving until the login restore has run | save on every canvasReady | the first draw of the active scene fires `canvasReady` before `ready` and would overwrite the view being restored |
| No scene-permission check before `scene.view()` | `testUserPermission(LIMITED)` | players view scenes they do not own (pulled, teleported); the saved scene is one they were already viewing |
| Small tier, new module | portals | portals is region teleport; this is client state at login |
