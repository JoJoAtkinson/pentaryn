# ZZ Playground - stations.json schema and station table

Generated by `gen.py` from the DSL in `gen.py` + `pglib.py`. One scene, **ZZ Playground**, 100x100 squares (10000x10000 px, grid 100 px = 5 ft, padding 0, no background image, a light background colour on the scene's level, global light on, darkness 0). It is not the table's active scene: view it, never activate it.

## Layout

Sixteen stations in a 4x4 grid of 25x25-square cells: S01-S04 the top row left to right, S05-S08 the second row, and so on. Each station owns the top-left **24x24 squares** of its cell (a one-square margin on the right and bottom, stations not connected). The top 2 rows of every station are the label band: a drawn title `Sxx - name` and a one-line instruction. Everything is in **pixels** in the JSON (square = 100 px); station-local square coordinates are only used inside `gen.py`.

Players do not see wall documents, so every wall is also drawn (a Drawing line: dark wall, brown closed door, green open door, red locked door, purple one-way wall with arrows, blue chasm edge). Door colours show the default state, the door controls show the live one.

## stations.json

```
{ grid: 100, cols: 4, rows: 4, cellSquares: 25, contentSquares: 24, labelBandSquares: 2,
  scene: { name, width, height, padding, backgroundColor, grid },
  actors: [ { name, type, size, width, walk, owner, disposition, linked } ],   // ZZ actors the build creates when missing
  stations: [ {
    id: "S01", name, instruction,
    cell: [c0, r0, c1, r1],            // squares, absolute, inclusive: the 25x25 cell
    area: [x0, y0, x1, y1],            // px of the 24x24 content area (x1,y1 are the far edges)
    walls: [ { c: [x0,y0,x1,y1],       // px
               door: 0|1|2,            // 1 door, 2 secret door
               ds: 0|1|2,              // door state: 0 closed, 1 open, 2 locked
               move, sight, light, sound,   // only when not the default 20 (chasm edges: move 20, others 0)
               dir: 0|1|2,             // one-way: 1 = blocks crossings from the LEFT of p0->p1 (measured in-world: open from the west for a wall drawn top to bottom)
               key,                    // doors and scenario walls: the name scenarios use
               grp,                    // polyline group (stair walls, S06 passages), used to measure widths
               only: [scenarios] } ],  // exists only in those scenarios
    regions: [ { key, name, kind: "mud", only, shape: {type: rectangle|polygon, ...px} } ],   // core modifyMovementCost, walk x2, visibility Always
    tokens: [ { name, actor, x, y, w, h,          // px top-left, size in squares
                owner: "A"|"B"|null,              // ZZ Player8A / ZZ Player8B (all the player's own tokens are in the actor's ownership)
                disposition: 1|0|-1, hidden, hero, linked, role, only } ],   // hero = player-owned (gets sight in mode sight); only = scenario-only token
    scenarios: { default: {note, tokens: {}, doors: {}},
                 <name>: { note, tokens: { tokenName: [x, y] },   // px start positions that differ
                           doors: { doorKey: ds },                 // door states that differ
                           combat: { tokens: [names], initiative: {name: n}, turn: name } } },   // starts a combat
    points: { name: { c: [cx, cy], note } },     // named spots for drops: CENTRE of the spot, px
    measure: { name: { groups: [grpA, grpB], width, tol, note } },   // narrowest clear width in squares, checked by verify.js
    drawings: [ { t: rect|poly|line|text, ... } ]  // floors, wall lines, labels (build.js turns them into Drawings)
  } ] }
```

Token names carry the station (`S03 Hero 2`), are always displayed, rotation is locked, tokens are tinted by role (green hero/friend, red monster, yellow villager, purple target, grey prop). Hero tokens are **linked** tokens of the ZZ Hero actors (Hero 1-4, Large, Huge, Slow Hero, Fast Hero 1-3 belong to ZZ Player8A; Hero 5-8, Tiny, Horse, Rider to ZZ Player8B); everything else is an unlinked token of ZZ Monster, ZZ Target or ZZ Villager. Every document carries `flags.world.pg = {st, key, grp, only}` so the reset can find its own.

## Scenarios and the reset

`reset.js` takes `globalThis.PG = { mode: "paths"|"sight", station: "all"|"Sxx", scenario: "default"|<name> }` and is self-contained (macro, eval-js and the pt harness all run it). `station: "all"` with a scenario applies it to every station that has it, the others stay default. Mode **paths** (default): token vision off, fog off. Mode **sight**: token vision on, fog exploration on and wiped, sight on the player-owned hero tokens only (station `all`: every hero; `Sxx`: that station's heroes). Either mode: every token of the chosen station(s) back on its start square, doors, regions and scenario walls restored, the scene's combats deleted, movement history cleared, stray tokens removed (also unflagged tokens dropped inside a station), selections released on the page that runs it. Run it with the playground viewed on that page (it views the scene itself when it is not).

Macros (folder **ZZ Playground**): `ZZ PG reset: paths (vision off)`, `ZZ PG reset: sight (heroes only)`, `ZZ PG scenario...` (dialog: station + scenario + mode). The journal entry **ZZ Playground** links them (a click on a macro link runs it) and lists the stations.

## Files

`gen.py` (+`pglib.py`, `tpl/`) writes `stations.json`, `stations.md`, `build.js`, `reset.js`, `install.js`, `verify.js`. `build.js` builds the scene (idempotent: it deletes only the scene named ZZ Playground, creates missing ZZ actors, builds walls/drawings, then runs the reset for tokens, doors and regions). `install.js` makes the macros and the journal. `verify.js` (`run-verify.sh`) writes `verify.json`. `shots.sh` writes `shots/`. All JS files are bodies of an async function.
