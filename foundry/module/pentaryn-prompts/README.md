# Pentaryn Prompt Markers (`pentaryn-prompts`)

Drop a **prompt marker** on a map, type what should be there, press **Esc**. Later Claude reads every
prompt in one call, with its surroundings already worked out, and replaces each marker with the real
thing in another. Design: [`context/plans/prompt-markers.md`](../../../context/plans/prompt-markers.md).
Playbook (how Claude uses it): `context/foundry/prompt-markers.md`.

## Install

```
make foundry-prompts-check     # parse + imports + i18n + node suite (Foundry can stay stopped)
make foundry-prompts-sync      # check, then copy into Data/modules
```

First install needs a **world restart** (module.json is read at startup), then enable *Pentaryn Prompt
Markers* and reload the one GM tab. On GM ready the module creates the **`Prompt Markers`** actor folder
and six actors, and repairs them on every later ready (never deletes).

| Actor | dnd5e size | Footprint |
|---|---|---|
| `Prompt · tiny` | tiny | 0.5 × 0.5 |
| `Prompt · small` | sm | 1 × 1, art at 0.8 |
| `Prompt · mid` | med | 1 × 1 |
| `Prompt · large` | lg | 2 × 2 |
| `Prompt · xl` | huge | 3 × 3 |
| `Prompt · xxl` | grg | 4 × 4 |

`flags.pentaryn-prompts.marker = "<size>"` (actor and prototype) is the recognition key, never the name.
Every marker token is forced hidden, sightless and `flags.dnd5e.lockSize` on creation. Art lives in
`assets/marker-<size>.webp`, generated by `./.venv/bin/python scripts/foundry/prompt_marker_art.py`
(`--data` also writes `Data/assets/tokens/custom/markers/prompt-<size>.webp`).

## Using it (GM)

- **Drag** a `Prompt ·` actor onto the map: the dialog opens beside it, caret in the box.
  Shift while dragging places it off-grid (v14).
- **P** places a marker of your client's default size under the cursor (always snapped);
  **Shift+P** opens the marker under the cursor.
- **Esc** saves and closes · **⌘/Ctrl+Enter** saves and closes · **Shift+Esc** puts the text back
  as it was when the dialog opened (on a freshly dropped marker that is empty, so the marker is
  removed; the footer says so) · **Enter** is a newline. Typing autosaves after 600 ms.
- **Type straight away.** From the drop (or P, double-click, HUD button) until the box has focus,
  keys are held by `typeahead.mjs` (a capturing `keydown` on `window`, ahead of core's hotkeys) and
  land in the box when it opens — they never reach the ruler, compendium or module hotkeys. ⌘/Ctrl
  shortcuts pass through. Each pending open has its own buffer (drop, type, drop, type → each box
  gets its own words). Held text no box claims within 3.5 s goes to the open box, else a toast.
  For 1.2 s after opening, focus that falls to the page body (the tail of a double-click) returns
  to the box.
- Every open is a **new window** (`pentaryn-prompts-dialog-<n>`): closing snapshots the text, removes
  the window at once (no fade) and saves in the background, so the next drop never waits on it.
  Dropping a new marker while a box is open closes (and saves) the old one.
- A freshly dropped marker closed empty is **deleted** (toast). A reopened one emptied by hand stays,
  red-tinted, named `Prompt · mid — empty`.
- Reopen: **double-click** (libWrapper `MIXED` on `CONFIG.Token.objectClass#_onClickLeft2`, wrapped by
  hand without libWrapper), the **Token HUD** bubble button, Shift+P, or `game.pentaryn.prompts.open(id)`.
- **Size chips** swap the marker for the other size actor centred on the same point, text carried.
- **Side panel**: what this marker can see (unlimited darkvision through walls, doors as they stand,
  light ignored), nearest first; collapsed *Out of sight (within 60 ft)* with `door` / `wall` tags.
  Anything blocked only by a door is also named above the list ("Behind a closed door: Nilonim
  Vrinn (10 ft W)", up to 3, 0.4.2).
  Click pans, ⌘-click opens the sheet / dialog. It redraws (250 ms debounce) when a wall or door on
  the scene changes, or a token or note is placed, moved or removed (0.4.1).
- Hover a marker: its full text, size and how many things it sees (under any open window).
- Nameplate: `✎ ` + the text with lines joined by ` / `, `…` only when cut at 40 characters.
- Built things whose biography is only `@Embed[…]` (compendium monsters) show the embedded page's
  text in the panel and the gather; other enricher markup is reduced to its label.

## API — `game.pentaryn.prompts`

| Call | Returns |
|---|---|
| `gather({scenes, crops, chars, unseenWithinFt, builtWithoutProvenance, maxPrompts, from, party, cropsAs})` | `{call, text, counts, manifest, crops, next, ms, version, party, partySource, cropsNote}` |
| `list()` | `{scenes: [{id, name, nav, prompts, empty}]}` |
| `crops({call, encounters, cropsAs})` | `{crops: [{encounter, scene, path \| png, mime, mimeType, squares}]}` |
| `replaceMany({call, replacements, dryRun, force, skipDryRun, party})` or `replaceMany({specFile, dryRun})` — the batch (`specFile`: a JSON file under the Data dir, `pentaryn-prompts-specs/<name>.json`, fetched by the browser: an array of replacements or `{call, party, replacements}`; dryRun/force only from the call) | `{dryRun, call, text, results, remaining, encounters}` — `text` is the readback the MCP tool prints, line for line; `results` are flat rows (below) |
| `replace(spec, opts)` — ONE replacement (`spec` = `{id, with, …}`; run options from `opts` or the spec) | same |
| `show({call, id})` / `show({sceneId, markerId})` | `{ok, sceneId, x, y}` (views the scene, pans, pings) |
| `status()` | `{version, listed, npcBridge, party, specDir, doubleClick, markers}` — `party` is the world setting or `"none set"`; `version` is the running code's own constant (`VERSION` in geometry-core.mjs, kept equal to module.json by the suite); `listed` is what `game.modules` says, which lags until a world rescan; `npcBridge` = the bridge's npc handlers are there |
| `open(tokenOrId)` · `place(size?)` · `ensureMarkers()` · `model(sceneId)` · `manifests()` · `version` | |

`scenes`: `"all"` (default: scenes holding prompts, nav order) · `"current"` · `[id or name, …]` (a
list may hold `"current"`; a single id or name string is a one-scene list, 0.4.2).
`crops`: `"auto"` (one scene with a background image or tiles → on; a blank scene → skipped, said in a `<crops>` line and `cropsNote`) · `true`/`"on"` · `false`/`"off"`. `cropsAs`: `"files"` (the API
default: uploaded to `Data/pentaryn-prompts-crops/<call>/E1.webp`, `path` returned, no base64 in an
eval-js result) or `"base64"` (what the queries — the bridge — get, turned into MCP images).
`party`: `"4x5"` / `{size, level}` / `[levels]`, default the world setting `party`; the text's `<party>`
line names it and its source, or says none is set (never guess); prints the 2024
DMG budget per encounter and is kept in the manifest for replace's difficulty readback. Paging: at most `maxPrompts`
(60) per call after the first scene; `next` is the scene id to pass as `from` with the same `scenes`.

**Queries** (`CONFIG.queries`, all GM-only — a non-GM sender is refused on `ctx.user`, and the client
running the handler must be a GM): `pentaryn-prompts.list`, `.gather`, `.crops`, `.replace`, `.show`,
args as above. Errors are `Error("<CODE>: detail")`: `TEXT_CHANGED`, `MARKER_GONE`, `CALL_UNKNOWN`,
`SCENE_UNKNOWN`, `BAD_SPEC`, `NOT_GM`, `CREATE_FAILED`.

### Replacement kinds

`{call, id: "p3" | sceneId, markerId, with, name?, hidden?, note?}` where `with.kind` is

- `actor` — `{actorId}` (place the world actor) or `{uuid}` (compendium → imported into
  `Foundry MCP Creatures`; `copy: true` on a world actor duplicates it). `patch` (`patch.mjs`):
  name, size, img, biography, hp, ac, cr, speed, disposition, `removeItems`, `addItems` (gear by
  name / uuid / inline `{data}`), `traits` (monster features with activation, recharge, uses),
  `recharge` on existing items, `itemUpdates`, `set`, `creatureType` (`"construct"`,
  `"humanoid (goblinoid)"`), `languages` (names or keys → dnd5e keys; replaces) — applied before the
  token is placed. A type change without `languages` clears the inherited ones (a construct made from
  an earth elemental does not keep Terran); `set["system.traits.languages.value"]` words become keys.
  Inline `{data}` items of a type that has attunement (weapon, equipment, consumable, tool, container)
  whose text requires attunement get `system.attunement: "required"` (printed as `DEFAULTED`); "does
  not require attunement" and the like are not read as requiring it, and a `loot` item is named
  instead (dnd5e loot has no attunement). The dry run prints the language keys a patch will write and
  that a type change clears the inherited ones.
- `character` (`character.mjs`, pure half `build-core.mjs`) — `{name, level, class, subclass,
  species, background, abilities, abilityMethod, choices, hp, size, spells, spellbook, items,
  allowOffList, startingEquipment, biography, img, folder}` — `folder` is an Actor folder id or name
  (found or created; default `Foundry MCP Characters`). Every problem is collected before anything
  throws: one `BAD_SPEC` lists them all (`problemsText`). Resolves the PHB/SRD items by name, validates the ability budget,
  and — in the dry run — every `choices` key against the advancements the build will step through
  (species, background, class levels 1..N, subclass, each capped at the character's level, what they
  grant, and the feats the choices name; unknown → `BAD_SPEC` listing the known ones), every choice
  VALUE the real run would refuse or silently drop (a level ASI over budget, an unknown `{feat}`, a
  string where `{feat}` / `{str: 2}` belongs, a Fighting Style or Versatile name not in the pool, an
  unknown Magic Initiate spell — `BAD_SPEC`, nearest names given), a pool-less spell choice left
  unanswered (`WARN … NOT CHOSEN` with the exact value shape), every spell against the class list, every item by name
  (a miss names the nearest PHB names: `Spellbook` → `Book`; `{data}` items accepted). Then it runs
  dnd5e's AdvancementManager steps headlessly (the same step list, synthesised steps and
  `performBulkUpdate` commit the window uses), with the caller's `choices` or a stated default — an
  unanswered language choice takes the species' tongue, then Common and the common ones, never sign
  language first; naming a language the advancement already grants (`common`) is ignored, not warned.
  The report carries the sheet's numbers (languages and feats included), `defaults` and `warnings`.
  **The dry run runs the same build on an unsaved actor** (`previewCharacter` → `runBuild(…, ghost)`:
  each manager's advanced clone is the next ghost, items go in with `updateSource`, the class's
  spellcasting ability is set as its `_onCreate` would), so its `sheet:`, `DEFAULTED` and `WARN`
  lines are the real run's — checked line for line live (plan §14). `startingEquipment: "A" | "B" |
  "none" | {class, background}` adds the PHB gear from `system.startingEquipment`
  (`startingEquipmentPlan`, packs through `Item5e.createWithContents`, a focus category → the first
  `CONFIG.DND5E.focusTypes` item as `DEFAULTED` unless `items` names one, a tool type → the tool the
  character is proficient in) or the wealth; a caster with nothing to cast through gets a WARN
  (`focusMissing`). Choice titles ending in *Choice* also answer to the bare title (`titleForms`).
  A Monk's weapons get Martial Arts' own enchantment (its "Master Simple Weapon" / "Master Light
  Martial Weapon" activities through dnd5e's `applyEnchantment`; dnd5e's `canEnchant` picks the
  weapons), so the Quarterstaff rolls DEX and the Martial Arts die from the first swing; the dry run
  names them in a note (0.4.3, usability Area 10). A new character starts with every spell slot full
  (leveled and pact, `system.spells.<key>.value = max` as dnd5e's long rest does, in the same write as
  full HP; the dry run's ghost too), and the `sheet:` line ends `slots 1st 4/4, 2nd 3/3` /
  `slots pact 2/2 (3rd)` (0.4.4, play test PT2-2: they were 0/4).
- `npc` — `{npc, features, patch}` (`npc.mjs`, pure half `npc-core.mjs`), **built by this module**
  since 0.3.0, so it works through eval-js too: `npc` is the dnd5e-create-npc arguments, `features`
  the dnd5e-add-feature arguments without `actorIdentifier` (+ `recharge`). Every field is checked and
  defaulted exactly as those tools did (unknown keys refused, with the known ones listed) in the dry
  run, then the actor is made through the bridge module's own handlers
  (`CONFIG.queries["foundry-mcp-bridge.createNpcActor"]`, `.add…ToActor`) in this GM client; language
  words become dnd5e keys (`Elven`, `Orcish` too; a word that is no language stays custom text), a
  name another NPC has is allowed (temporary name, renamed after), recharge is applied by the patch.
  A `spells` feature's names are looked up in its `compendiumPacks` in the dry run the way the bridge
  will (default `dnd5e.spells`, the 2014 SRD, as the tool defaulted): a miss is a `WARN` with the
  nearest names. The actor is the run's: deleted if the replacement fails later; a feature
  that would not add is a `notes:` line. `{kind: "npc", actorId}` and the older bridge form `{kind:
  "actor", actorId, copy: false, provenanceKind: "npc", stampActor: true}` still place an existing actor.
- `hotspot` — `{name, description, items: [{uuid | name, quantity, rename, system} | {data}], size = 0.5, locked, icon, light}` (`light`: an AmbientLight config placed at its centre, same provenance; the gather prints it as `Light:` on the hotspot); clones
  `Hotspot · Look (template)` the markers.md way (all four images, `deleteWhenEmpty: false`, lockSize).
- `note` — `{name, html, folderId, label, ownership = "observer", iconSize = 64, icon = eye, light}`;
  `global: false`.
- `light` — `{config, hidden}` · `tile` — `{src, width, height}` (squares) · `none` — `{reason}`.

Replacement-level: `name`, `hidden`, `note`, `ring` (`pc` | `foe` | `named` | `mook` | `none`;
characters default to `pc`), `img`, `disposition`.

**Result rows are flat** (strings, numbers, booleans, lists of strings — nothing an eval-js result can
lose to the bridge's serialisation depth limit), built by `readback-core.mjs`: real run `{index, id,
label, sceneId, markerId, kind, ok, code?, error?, created: ['Token "Yark" [id] @x,y 1x1', …], ids,
markerDeleted, sheet, patched, defaults, warnings, notes, discarded, reason?}`; dry run `{…, at,
placement, footprint, lockSize, hidden, creates, warnings, defaults}`. `encounters: [{id, xp,
creatures, unbuilt, budget, difficulty}]` for every manifest encounter the run built into (hostile
npcs only). The MCP tool prints `text` as it is.

Placement: same footprint → the marker's own x/y; other creature footprints centred and snapped;
hotspots/tiles centred unsnapped; notes/lights on the centre. lockSize whenever the width is not the
size category's; `hidden` explicit; elevation and level copied. Every created document (and the
created actor/journal) gets `flags.pentaryn-prompts.provenance = {prompt, size, footprint, sceneId,
markerId, call, pid, at, kind, note}`. More than 5 replacements need a dry run of the same marker set
first (counted as the replacements the call asks for, valid or not; this GM page's lifetime; otherwise `DRY_RUN_REQUIRED`) unless `skipDryRun: true` — the bridge
passes it, because it keeps its own identical-spec gate. Hotspot item uuids are
resolved at plan time, so a bad one fails the dry run. A failed replacement keeps its marker, and any
actor/journal this module created for it (import, copy, hotspot clone, note journal) is deleted again
(`discarded` in its result); the rest go through.

## Geometry, briefly

Distance is between nearest occupied squares under the world's diagonal rule (adjacent = 5 ft);
bands `touching 5 | reach 10 | close 15–30 | near 35–60 | far 65–150 | distant 155+`; 8-point bearing,
north up. Sight: core's `polygonBackends.sight.testCollision` on the item's Level, then a door-only
pass over the wall documents for blocked pairs (`door` / `secret door` / `wall`; proximity thresholds
honoured as core does). Sight is lazy: a pair is tested only when the text, the panel or the grouping
reads it, and the door pass only runs for blocked pairs that get printed (within `unseenWithinFt`, or a
loner's nearest neighbour). Measured: ~95 µs per core test on a 1,578-wall scene, ~9 test points per
1×1 token, so a blocked pair costs ~0.7 ms. Encounters link at
≤30 ft with sight either way; formations at ≤15 ft; built things join but never bridge. **A hostile
built creature brings its pack** (the hostile built creatures chained to it at ≤30 ft with sight), so
a prompt dropped beside one goblin of a built camp joins the whole camp. Neutral and friendly built
creatures (crowds, the innkeeper, the party) and objects (hotspots, notes, lights, tiles) join only
where they stand within 30 ft of a prompt and never chain — the Molten Ward's 45 neutral street
tokens would otherwise chain into one 18-token "encounter" around any prompt. **One prompt with a
hostile built creature is an encounter**; one prompt beside built objects or non-hostile creatures
only is "alone" and those become context only (the loner's line names the nearest one it sees). A
pack two prompt groups reach is `shared` by both (never merged; the line says so). Ids: groups by
size then reading order, `E#` for groups of 2+ prompts or one prompt with a hostile built creature,
`p#` by group, size desc, reading order. The `call` id
hashes scene ids, marker ids, texts **and each marker's `p#`**, so a call always names one numbering: a
move or a door that renumbers the board makes a new call, and a replace written against the older text
still resolves through the older manifest. All of it is
`geometry-core.mjs`, pure and covered by `node test/run.mjs` (snapshot in `test/snapshots/`).

The overview also prints door lines (`doorLines`: each door a prompt group within `unseenWithinFt`
can see, its state, and which groups see it from which side — a sight line from a member to the
doorway with every other wall counting, the side taken from the door's own line; past another closed
door → `through another door`; a prompt group in range that cannot see it at all is listed after the
sides as `No sight line to it: p2 (20 ft, wall)`, never on a side; context-only built things are named
for the nearest three per side, the rest counted as `+N more built`), the nearest built thing a loner can see, what blocks two encounters (`a
closed door` / `wall`), and `elev="10 ft"` on any item off the ground. Encounter lines name their
built members (`+ built t4 "Skrag", t5 "Grek"`) and their XP. `<built>` carries `type` (a character:
`Paladin 5, Oath of Devotion (Human)`), `stats` (`CR 1/4, AC 15, HP 11`), `disposition`, a hotspot's
`Items:` (the item's real name, rarity, `unidentified, shows as "…"`, attunement — read from the item
source, since dnd5e's derived data of an unidentified item hides both) or a creature's notable `Carries:`, the
provenance `note` as `Why:`, and the description cut at a sentence (`previewSentences`, `gatherChars` 400).
A description is printed once per actor: further unlinked tokens of that actor with the same text say
`Description: same as t4 "Goblin"` (0.4.4, play test PT2-5); a token whose text differs prints its own.
When that own (delta) text is cut, the pointer names the token, not `get-character <base id>` (which
prints the base actor's text): `… (cut, this token's own text: eval-js fromUuidSync("<token uuid>").actor.system.details.biography.value)` (0.4.5).

Not modelled: wall heights / Levels elevations (the gather prints a `WARN` line). Hex grids count
hexes (cube distance over core's occupied offsets); notes, lights and tiles occupy the hex under their
centre.
